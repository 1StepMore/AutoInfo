## 4. 会咬你的坑（按疼痛程度排序）

1. **pre-commit 会整文件重排，然后中止你的提交。** 仓库整体**未过 `ruff format`**（本轮开始时 `HEAD` 上 `ruff format --check src/` 报 **71 个文件**，收尾时仍剩 **46**），而 `.pre-commit-config.yaml` 的 `ruff-format` / `ruff --fix` 只处理**被暂存的文件**、且重写**整个文件**而非你改的 hunk。后果：你只改一行，提交时却带上几十行风格改写，且提交**第一次一定失败**（钩子改了文件就中止）—— 重新 `git add` 再提交一次即可。这不是 bug，是仓库现状；根治方式（单独做一次全量格式化提交 + 加 CI format 门禁）已登记为残余，本轮未做。
2. **改动文件 ruff 门禁没有基线豁免。** `ci.yml` 的 `ruff check <changed files>` 会因**预存量**错误变红（我就是因此被迫清掉 `api/server.py`、`email_sender.py`、`billing.py` 里 5 条既有 E501/N806）。规则：**你碰过的文件必须 lint 干净**，287 条预存量只允许留在没碰的文件里。
3. **没有 LLM key 时，个别集成测试会跑 ~200s 然后被 `--timeout=180` 杀掉**，看起来像回归。判定方法见下一节 —— 先做 HEAD 对照，别急着改代码。
4. **`tests/TRIAGE.md` 的总数是算出来的。** 守护测试用正则在权威章节里抓「不以 `|` 开头的裸 node id 行」，断言 `基线失败数 == 列表长度`。所以：新增说明性文字请放进**表格行**或非权威章节，否则会把守卫弄红。
5. **`.pre-commit-config.yaml` 的 `no-credential-url` 钩子会扫到它自己**（配置里含 URL 样例）。要提交这个文件时钩子必然报错 —— 已登记为残余，别浪费时间修。
6. **本环境会吞掉 shell 变量与 `$` 转义**（`awk '{print $2}'`、`for f in ...`、`$f` 全失效，`§` 也会被吃掉）。改用 `xargs -a file`、显式路径、`git diff --numstat` 这类不依赖变量的写法；提交信息用文件传（`git commit -F /tmp/msg.txt`）而不是内联 heredoc。
7. **改 CI job 名会打断分支保护。** `Mypy (changed files)` 等名字是 `GOVERNANCE.md` 里的**必需状态检查名**，所以我加了全树 mypy **步骤**而不是新 job。
8. **计数契约**：`ci.yml` 顶部注释自己写明「若全树 ruff 计数变动，必须**同轮**更新此处与 `pyproject.toml` 的 per-file-ignores 注释」。动代码时顺手看一眼。
9. **`knowledge/`、`.autoinfo/`、`autoinfo.db`、`outputs/` 都是 gitignore 的运行时产物**，不是源码。不要为了让测试变绿去改它们；要改行为就改 `src/`。

### 怎么判定「这是不是我引入的回归」

不要靠读代码猜，用 detached worktree 做对照（本轮的两次归因都靠它）：

```bash
# 1) 在改动前的 HEAD 上开一个干净 worktree
git worktree add --detach /tmp/baseline_head HEAD
# 2) 关键：把运行时产物也搬过去，否则环境不等价
cp -r .autoinfo knowledge autoinfo.db /tmp/baseline_head/
# 3) 用 PYTHONPATH 指向基线 src 跑同一个 node id
cd /tmp/baseline_head && PYTHONPATH=/tmp/baseline_head/src \
  /mnt/d/贯维/AutoInfo/.venv/bin/python -m pytest "<node id>" -q --timeout=180 -p no:cacheprovider
# 4) 收工
git worktree remove --force /tmp/baseline_head
```

判据：**同一个 node id 在基线也失败 → 非本次引入**（登记进 `TRIAGE.md`，不要顺手"修"到预算里）；基线通过而当前失败 → 是真回归，修。
