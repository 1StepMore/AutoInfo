## B1 — `AUTOINFO_LLM_API_KEY` absent: T12 and T13 cannot run

`.autoinfo/config.yaml` resolves `llm.api_key: ${AUTOINFO_LLM_API_KEY}`; the
variable is unset in this environment, so every LLM path returns
`LLM_NOT_CONFIGURED`.

Per the plan, **T12 and T13 were not started at all**. Running extraction without
a key is worse than not running it: extraction failures are non-fatal and store
empty results, which then fail G3 — the run would produce a hollow `01-Raw` and
a Draft/Wiki tier built on nothing.

Consequences, recorded instead of hidden:

- `01-Raw` / `02-Draft` / `03-Wiki` rebuild for this run: **not done**.
  On-disk state stays medical-research 39 Raw / 0 Draft / 0 Wiki,
  language-learning 26 / 0 / 0, ai-commercial 5 / 0 / 0 — no Draft or Wiki
  entry was fabricated by hand to satisfy the acceptance criteria.
- Of the 81 feature rows in T17, the **36 LLM-dependent rows are reported as
  L1–L2 only, L3 = `blocked-no-llm-key`**; the **45 non-LLM rows** still get the
  full treatment (produce the artifact, check L0 and L2).
- Cost accounting for LLM rows is `unknown`, not `0`.

Unblock: export a key (`export AUTOINFO_LLM_API_KEY=...`), then run T12 and T13
as written. Nothing else in the pack depends on the key.
